# Технический долг

## 1. Фиксация сроков полномочий ГД и их прекращение по событиям

**Описание:** Система хранит `gd_term_id` (срок полномочий ГД) в `legal_entity_charter`, но не отслеживает:
- Дату начала полномочий действующего ГД
- Дату окончания полномочий
- Автоматическое уведомление об истечении срока
- События прекращения полномочий (смерть, дисквалификация, решение суда, добровольная отставка)

**Правовая основа:**
- ст. 40 14-ФЗ — избрание ГД ОСУ
- п. 2 ст. 33 14-ФЗ — исключительная компетенция ОСУ по избранию/прекращению
- ст. 32¹ 14-ФЗ — основания прекращения полномочий (аналог ст. 66¹ 208-ФЗ)

**Требуемые изменения:**
1. Новая таблица `gd_appointments`: `legal_entity_id`, `person_id`/`full_name`, `appointed_by_osa_meeting_id`, `start_date`, `end_date`, `termination_event`, `status`
2. Автоматический расчёт `end_date` на основе `gd_term_id` и `start_date`
3. Cron/уведомление за 30/60/90 дней до истечения срока
4. Обработка событий прекращения: смерть, дисквалификация (из РДЛ), добровольная отставка (заявление), решение ОСУ

## 2. Договор с управляющей организацией

**Описание:** ст. 42 14-ФЗ допускает передачу полномочий ЕИО не только ИП, но и управляющей организации (юрлицу). В текущей реализации поддерживается только ИП.

**Требуемые изменения:**
1. Расширить `llc_management_contracts` или создать отдельную таблицу
2. Добавить атрибуты юрлица: наименование, ИНН, ОГРН, КПП
3. UI для выбора типа: ИП / Управляющая организация

---

## 3. Уникальность договора с управляющим

**Описание:** В АО действует уникальный индекс `ux_ao_contractors_le_type_active` — не более одного активного договора каждого типа на ЮЛ. Для ООО таких ограничений нет. Нужно определить бизнес-правило: может ли ООО иметь несколько действующих договоров с управляющими одновременно?

**Требуемые изменения:**
1. Определить бизнес-правило (ст. 42 14-ФЗ не запрещает, но на практике обычно один управляющий)
2. При необходимости — добавить уникальный индекс или валидацию на уровне приложения

## 4. Требование о смене ГД / передаче полномочий управляющему ИП

**Описание:** Требование о смене ГД и требование о передаче полномочий управляющему ИП — это один и тот же процесс (ст. 42 14-ФЗ). Текущий flow «требование → решение ГД → исполнение» не покрывает сценарий, когда вместо избрания нового ГД полномочия передаются ИП-управляющему. В seed-данных `ref_request_type` нет типа для такой операции.

**Правовая основа:**
- ст. 42 14-ФЗ — передача полномочий ЕИО управляющему (ИП или управляющей организации)
- п. 2 ст. 33 14-ФЗ — исключительная компетенция ОСУ

**Требуемые изменения:**
1. Добавить тип требования `DEMAND_CEO_REPLACEMENT` (смена ГД) с подтипом: избрание нового ГД / передача полномочий ИП-управляющему
2. Реализовать flow: требование → ОСУ → решение → (а) избрание нового ГД ИЛИ (б) заключение договора с управляющим ИП
3. При варианте (б) — автоматическое заполнение формы создания договора с управляющим из результатов ОСУ

## 5. Периодическая проверка статуса ЮЛ/ИП с действующими договорами

**Описание:** Система не отслеживает изменения статуса контрагентов (регистраторов, информационных агентств, управляющих ИП) после заключения договора. Контрагент может быть ликвидирован, исключён из ЕГРЮЛ/ЕГРИП, признан банкротом или лишён лицензии — а действующий договор останется активным в системе.

**Правовая основа:**
- ст. 61 ГК РФ — основания ликвидации юридического лица
- ст. 22.1 129-ФЗ — основания исключения из ЕГРЮЛ
- ст. 22.4 129-ФЗ — основания исключения ИП из ЕГРИП
- 39-ФЗ — лицензирование деятельности регистраторов (ведения реестра)

**Требуемые изменения:**
1. Cron-задача (1 раз в сутки/неделю): запрос статуса контрагентов через СПАРК/ЦБР для всех действующих договоров
2. При обнаружении недействительного статуса — создание задачи (org_task) с типом `CONTRACTOR_STATUS_INVALID`
3. Уведомление LAWYER/CEO о проблеме с контрагентом
4. Автоматическая деактивация договора при подтверждении ликвидации (опционально, по настройке)
5. Журнал проверок (`contractor_status_checks`): дата проверки, предыдущий/новый статус, источник
