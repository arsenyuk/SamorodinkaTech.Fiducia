# E2E-тест: Требование участника о созыве ВОСУ

> **Связанные документы:** [Сквозные тесты](e2e-tests.md)

## Сценарий

### Бизнес-условие

Участник ООО с достаточной долей (≥ порога ВОСУ) подаёт требование о созыве внеочередного общего собрания участников (ВОСУ). Требование проходит полный цикл: регистрация участника → ЕДИН-привязка → подача требования → решение CEO → формирование плана ВОСУ → уведомления.

### Кто что делает

| Шаг | Действие | Исполнитель |
|-----|----------|-------------|
| 0 | Подготовка окружения | Автоматически |
| 1 | Регистрация участника с ДУЛ + доля 40% | ГД (`kazakov.nv`) |
| 2 | Ожидание ЕДИН-привязки (MasterId) | Автоматически |
| 3 | Подача требования «Требование о созыве ВОСУ» | Участник (`frolov.sa68`) |
| 4 | Решение CEO: «Принять требование» | CEO |
| 5 | Проверка: «Данное требование инициировало созыв ВОСУ» | Автоматическая (assert) |
| 6 | Заполнение формы плана ВОСУ (дата, время, место, повестка) | CEO |
| 7 | Формирование уведомлений + проверка ссылок на скачивание | Автоматическая (assert) |

## Действующие лица

| Роль в системе | Логин | Как создаётся | Место в тесте |
|----------------|-------|---------------|---------------|
| ГД + Администратор ЮЛ + Участник общества | `kazakov.nv` | LDAP + Admin Console (LE_ADMIN) + Board Portal (CEO) | Шаг 1–2 |
| Участник общества | `frolov.sa68` | LDAP + Board Portal (PARTICIPANT через ЕДИН) | Шаг 3 |
| CEO | Назначается при привязке BoardParticipant | Board Portal | Шаг 4–7 |

## Предусловия

1. Инфраструктура запущена
2. БД сброшена
3. ЮЛ сидировано (entityIndex 67)
4. ЮЛ настроено: нетиповый устав, порог ВОСУ, ExecutiveBody=A

## Шаги теста

### Шаг 1: Регистрация участника

**Исполнитель:** `kazakov.nv`

**Действие:**
```
BoardPortalHelper.AddParticipantWithPersonalDataAsync(boardPage,
    fullName: "Фролов Станислав Андреевич",
    dulTypeCode: "21", dulSeries: "4690", dulNumber: "111222",
    personInn: "781234567890",
    sharePercent: 40,
    ecosystemParticipantId: <id>)
```

### Шаг 2: Ожидание ЕДИН-привязки

**Действие:**
```
EdinTestHelper.WaitForEdinBindingAsync(boardPage, participantId, timeoutSeconds: 15)
var masterId = await EdinTestHelper.GetParticipantMpiMasterIdAsync(boardPage, participantId)
```

**Проверка:** `masterId.Should().NotBeNullOrWhiteSpace()`

### Шаг 3: Подача требования

**Исполнитель:** `frolov.sa68`

**Действие:**
1. Логин в Board Portal
2. Навигация на «Мои запросы»
3. Клик «Подать требование»
4. Выбор «Требование о созыве ВОСУ»
5. Заполнение textarea с текстом требования
6. Установка галочки `#agreeWarning`
7. Отправка формы

**Проверка:** URL содержит `/share-requests`

### Шаг 4: Решение CEO

**Действие:**
1. CEO логинится
2. Навигация на «Оповещения»
3. Поиск уведомления «Требование участника о созыве ВОСУ»
4. Клик по ссылке уведомления
5. Клик «Принять требование» (подтверждение диалога)

**Проверка:** Появляется кнопка «Перейти к плану ВОСУ»

### Шаг 5: Проверка статуса

**Проверка:** На странице отображается пометка «Данное требование инициировало созыв ВОСУ»

### Шаг 6: Форма плана ВОСУ

**Действие:**
1. Заполнение даты: `2026-06-15`
2. Заполнение времени: начало `14:00`, регистрация `13:30`
3. Заполнение места проведения
4. Заполнение повестки
5. Клик «Сформировать уведомления»

### Шаг 7: Проверка уведомлений

**Проверки:**
- Секция «Сформированные уведомления» отображается
- Ссылки на скачивание: `a[href*='/api/files/']`
- URL содержит `/ceo-demands/`
