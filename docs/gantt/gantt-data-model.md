# Модель данных диаграммы Ганта

Эта статья описывает соглашения, принятые в диаграммах Ганта проекта. Здесь — устройство модели: столбцы, префиксы, вехи, фазы, сценарии и связь с таблицами документооборота.

---

## 1. Столбцы таблицы

Каждая задача описывается строкой:

| Столбец | Тип | Описание |
|---------|-----|----------|
| **ID** | `строка` | Уникальный код задачи. Префикс — категория, номер — порядок |
| **Задача** | `строка` | Название задачи — что именно делается |
| **Исполнитель** | `строка` | Роль, выполняющая задачу. Стрелка (`→`) означает делегирование |
| **Длительность** | `целое` | Рабочих дней (раб. дн.) или календарных дней (кал. дн.). Для вех — `0` |
| **Начало** | `дата` | Дата старта. Для вех — дата наступления |
| **Конец** | `дата` | Дата завершения. Расчёт: `Начало + Длит. − 1`. Для вех — равна дате начала |
| **Предшественники** | `строка` | ID задач, которые должны быть завершены до старта данной. `—` — нет зависимости. Несколько — через запятую |
| **Примечание** | `строка` | Детали выполнения, ссылки на таблицы документооборота |

> **О единицах измерения.** Длительность задач — в рабочих днях (раб. дн.) или календарных днях (кал. дн.), указано в ячейке столбца «Длит.». Законодательные дедлайны (сроки уведомления, публикации, подачи документов) — в **календарных днях** и указаны в столбце «Примечание» со ссылкой на норму закона. Например: «−30 кал. дн.» (п. 1 ст. 36 14-ФЗ), «−21 кал. дн.» (ст. 52 208-ФЗ). Не путать: 30 календарных дней ≈ 22 рабочих (с учётом выходных и праздников).

---

## 2. Категории задач (префиксы ID)

Каждая задача получает ID вида `<Префикс><Номер>`. Префикс задаёт категорию (исполнитель или предметную область), номер — порядок. Полный перечень префиксов — в каждой конкретной диаграмме.

---

## 3. Вехи

**Веха** — контрольная точка с нулевой длительностью. Наступает, когда все её предшественники завершены. Не имеет исполнителя. Примеры: готовность документа, получение заключения, завершение этапа.

- Вехи имеют **длительность 0** и **не установленную дату окончания** (дата окончания равна дате начала).
- **Название вехи** всегда формулируется **в прошедшем времени** (например: «Отчётность готова», «Заключения получены»).

---

## 3.1. Маркировка SS (Start-to-Start)

Маркировка **SS** в столбце «Начало» обозначает, что задача начинается **одновременно с началом фазы**. Формат: `SS` (в столбце «Начало»), `SS + <дни>` (в столбце «Конец»).

Пример:

```
| Р1 | Передача документов ревизору | ... | 1 раб. дн. | SS | SS | — | Параллельно с А2 |
```

Это используется для задач, которые стартуют в начале фазы (одновременно с другими задачами фазы).

---

## 3.1.1. Маркировка FS (Finish-to-Start)

**FS** (Finish-to-Start / Финиш-Старт) — стандартный тип зависимости: задача начинается **после завершения** предшественника. Это значение по умолчанию — если в столбце «Предшественники» указан ID задачи без маркера, зависимость автоматически FS.

Формат: `FS` (явно) или просто ID предшественника (неявно).

Примеры:

```
| П3 | Подготовка материалов | ... | 3 раб. дн. | Д−22 | Д−20 | П2 | FS: П3 начинается после завершения П2 |
| Б1 | Подготовка бюллетеней | ... | 2 раб. дн. | Д−19 | Д−18 | П2 | Неявный FS: указан только ID предшественника |
```

В таблицах проекта FS используется **неявно** — в столбце «Предшественники» указывается ID задачи, и задача стартует на следующий рабочий/календарный день после его завершения.

Отличия SS и FS:

| Тип | Обозначение | Смысл | Формат в «Начало» |
|-----|------------|-------|-------------------|
| **SS** | `SS` | Задача стартует в начале фазы | `SS` |
| **FS** | ID предшественника | Задача стартует после завершения предшественника | Конкретная дата или `Д+N` |

---

## 3.2. Контрактные вехи (Contractual Milestones)

**Контрактная веха** (юридическая / договорная / контрактная) — несдвигаемый дедлайн, установленный законом, уставом или договором. В отличие от обычных вех (которые свободно перемещаются в зависимости от графика), контрактная веха **привязана к фиксированной дате или событию** и не может быть сдвинута.

Маркировка: `⚡КВ*` в столбце ID (молния = несдвигаемость).

Формат строки:

```
| ⚡КВ1 | Уведомление акционеров — дедлайн | — | — | 24.04 | 24.04 | — | Ст. 52 208-ФЗ: −21 кал. дн. до ГОСА |
```

| Столбец | Значение |
|---------|----------|
| **ID** | `⚡КВ1`, `⚡КВ2`, ... |
| **Задача** | Описание дедлайна |
| **Исполнитель** | `—` (дедлайн не имеет исполнителя) |
| **Длит.** | `—` (нулевая длительность) |
| **Начало** | Дата дедлайна |
| **Конец** | Та же дата |
| **Предшественники** | `—` |
| **Примечание** | Норма закона/договора и расчёт даты |

Отличия от обычных вех (`▼В*`):

| Обычная веха (`▼В*`) | Контрактная веха (`⚡КВ*`) |
|----------------------|---------------------------|
| Внутренний контроль | Внешнее требование (закон/договор) |
| Свободно сдвигается | **Несдвигаемая** |
| Название в прошедшем времени | Формулировка — описание дедлайна |
| Зависит от предшественников | Привязана к фиксированной дате |

---

## 3.3. Межэтапные вехи (Phase Gates)

**Межэтапная веха** (веха-шлюз / Phase Gate) — контрольная точка между фазами, чётко разделяющая завершение одной фазы и начало следующей. В отличие от обычных вех (которые находятся внутри фаз), межэтапная веха **вынесена между фазами** и не принадлежит ни одной из них.

Маркировка: `▼ВР*` в столбце ID (ВР = веха-разделитель).

Формат строки:

```
| ▼ВР1 | Фаза 1 завершена | — | — | 31.01 | 31.01 | Б2 | Все задачи Фазы 1 выполнены |
```

| Столбец | Значение |
|---------|----------|
| **ID** | `▼ВР1`, `▼ВР2`, ... |
| **Задача** | Описание контрольной точки (формулировка в прошедшем времени) |
| **Исполнитель** | `—` |
| **Длит.** | `—` (нулевая длительность) |
| **Начало** | Дата наступления |
| **Конец** | Та же дата |
| **Предшественники** | Последняя задача предыдущей фазы |
| **Примечание** | Описание условия перехода |

На диаграмме Ганта межэтапная веха рисуется **точно посередине** между фазами. От вехи проводится **пунктирная линия** вверх и вниз, визуально отделяя фазы друг от друга.

В таблице строка `▼ВР*` располагается **между строками-заголовками фаз** — после последней задачи предыдущей фазы и перед заголовком следующей фазы.

Отличия от обычных вех:

| Обычная веха (`▼В*`) | Межэтапная веха (`▼ВР*`) |
|----------------------|-------------------------|
| Внутри фазы | **Между** фазами |
| Зависит от задач своей фазы | Зависит от последней задачи предыдущей фазы |
| Не визуализируется как разделитель | Пунктирная линия вверх-вниз на диаграмме |

---

## 3.4. Интеграционные вехи (Integration Milestones)

**Интеграционная веха** — точка синхронизации критических путей. Это единственная сущность в таблице, которая **может иметь несколько предшественников**. Задачи и этапы — не могут.

Маркировка: `▼ИН*` в столбце ID (ИН = интеграция).

Формат строки:

```
| ▼ИН1 | Материалы и повестка готовы | — | — | 15.04 | 15.04 | РГ4, П1 | Сходятся два критических пути |
```

| Столбец | Значение |
|---------|----------|
| **ID** | `▼ИН1`, `▼ИН2`, ... |
| **Задача** | Описание точки синхронизации |
| **Исполнитель** | `—` |
| **Длит.** | `—` (нулевая длительность) |
| **Начало** | Дата наступления (максимум из дат завершения предшественников) |
| **Конец** | Та же дата |
| **Предшественники** | 2+ ID задач (параллельные критические пути) |
| **Примечание** | Какие пути сходятся |

**Правило:** Если задача依赖 от 2+ предшественников — перед ней **обязательно** ставится интеграционная веха. Сама задача затем имеет FS-зависимость только от интеграционной вехи.

Пример:

```
| РГ4 | Проверка списка | ... | 1 р.д. | ... | ... | РГ3 | |
| П1  | Формирование повестки | ... | 2 р.д. | ... | ... | СД3 | |
| ▼ИН1 | Список и повестка готовы | — | — | 10.04 | 10.04 | РГ4, П1 | Сходятся два пути |
| П2  | Сборка пакета материалов | ... | 3 р.д. | ... | ... | ▼ИН1 | Только от вехи |
```

---

## 4. Фазы

Задачи группируются в **фазы** — хронологические блоки, разделённые строками-заголовками в таблице. Фаза не является строкой с ID — это визуальный разделитель. Фазы едины для всех сценариев одной диаграммы, длительность фазы может различаться.

---

## 5. Критический путь

В начале каждого сценария указана цепочка задач критического пути — самая длинная нерастяжимая последовательность зависимых задач. Задержка любой задачи на этом пути сдвигает конечную дату. Задачи на критическом пути помечены в столбце «Примечание».

---

## 6. Сценарии

Одна диаграмма может содержать несколько сценариев для разных условий. Сценарии различаются набором задач, критическим путём и датами. Фазы, вехи и исполнители — общие.

---

## 7. Документооборот

Каждая диаграмма дополняется справочными таблицами, описывающими артефакты:

| Таблица | Что содержит |
|---------|-------------|
| **СЭД** | Внутренние документы: приказы, поручения, проекты. Получатель — внутри компании |
| **Заказные / email** | Отправления, где важен факт и дата: уведомления, заявления |
| **Рассылки** | Что, кому и в какой срок: уведомления, копии протоколов. **Не включает** передачу рабочих материалов — это задачи, а не рассылки |

Связь между Гантом и таблицами документооборота — через индексы в столбце «Примечание». Индекс в Ганте ведёт на строку в соответствующей таблице.

---

## 8. Временна́я шкала диаграммы

Временна́я шкала — горизонтальная ось над или под таблицей задач, показывающая ход времени. В проекте используются два представления:

### 8.1. Линейная шкала (дедлайны)

Временна́я линия с отсечками, где каждая метка — крайний срок:

```
01.01 ────────────────────────────────────────── 30.04
  │                                                    │
  ├── до 15.01 ── Подготовка годового отчёта            │
  ├── до 01.02 ── Подготовка отчётности                 │
  ├── до 15.02 ── Передача материалов ревизору          │
  ├── до 01.03 ── Получение заключений                  │
  │                                                    │
  │  01.03 ───────────── ОКНО СОБРАНИЯ ──────── 30.04   │
  │      │                                              │
  │      ├── 01.04 ── Дата собрания                     │
  │      ├── +7 раб. дн. ── Подача в ФНС                   │
  │      └── +60 дн. ── Выплата прибыли                 │
  └── 30.04 ── Крайний срок                             │
```

Используется в чеклистах (раздел «Сроки и дедлайны»). Показывает критические даты, но не длительность задач и не параллельность.

### 8.2. Событийная шкала (относительная)

Отсчёт от даты собрания — дни «до» и «после»:

```
Д-25   Д-24   Д-22   Д-21   Д-20        Д-0       Д+4   Д+7
  │      │      │      │      │           │         │      │
  │      │      │      │      │           │         │      │
  ▼      ▼      ▼      ▼      ▼           ▼         ▼      ▼
фиксация быстрый полный уведом. доступ   ГОСА     раскрыт. ФНС
списка   список  список  акц.    матер.           проток.
```

Используется в Гант-таблицах (столбцы «Начало»/«Конец»). Смещения от события устойчивы к переносу даты собрания.

### 8.3. Связь двух шкал

Обе шкалы описывают один и тот же процесс, но с разных ракурсов:

| | Линейная | Событийная |
|---|---|---|
| **Где** | Чеклист, раздел «Сроки» | Гант-таблица |
| **Что показывает** | Дедлайны (к какому числу) | Даты начала и конца каждой задачи |
| **Привязка** | К календарю | К дате собрания |
| **Перенос собрания** | Требует ручного пересчёта | Сдвигается автоматически |

## 9. Заливка временны́х областей

### 9.1. Фоновая заливка (Background Shading)

Область временно́го периода — заливка фона за полосами задач, визуально разделяющая шкалу на смысловые отрезки. В интерфейсах программ применяются следующие названия:

| Термин | Описание |
|--------|----------|
| **Background Shading** | Фоновая заливка / область периода времени — общее название для любого цветного фона на временно́й шкале |
| **Time Period Area** | Область периода времени — то же, что Background Shading; подчёркивает принадлежность участка шкалы к интервалу дат |

### 9.2. Зебра (Zebra Shading)

**Зебра** — автоматическая полосатая заливка для чередующихся периодов (например, выделение недель или месяцев). Чередование светлых и тёмных полос позволяет глазу быстрее ориентироваться на шкале, не требуя ручной настройки каждого участка.

### 9.3. Приоритет заливок

При наложении нескольких типов заливок на один участок шкалы действует следующий приоритет (чем меньше число, тем выше приоритет):

| Приоритет | Тип заливки | z-index | Визуализация | Описание |
|-----------|------------|---------|-------------|----------|
| **0** | Запрет работы | 6 | Сплошная заливка + штриховка | Максимальный приоритет — периоды, в которые работа запрещена (например, mandated moratorium), перекрывают все остальные области, включая задачи, праздники и юридические окна |
| **1** | Праздники и выходные | 5 | Зебра (полупрозрачная) | Полосатая заливка нераб. дн. прорисовывается поверх фона и задач, но под областью запрета работы |
| **2** | Задачи и этапы | 2 | Сплошной бар | Бары задач и скобки этапов отображаются поверх юридических окон |
| **3** | Юридические окна | 1 | Фоновая заливка + штриховка | Окна возможностей и иные юридически значимые периоды отображаются **под** задачами как цветной фон

## 10. Визуализация вех на диаграмме Ганта

Компонент `GanttChart` отображает вехи с учётом их типа (`GanttMilestoneType`). Тип вехи определяет визуальное оформление: размер ромба, наличие вертикального пунктира и цвет.

### 10.1. Типы вех и их визуальное представление

| Тип | Русское название | Префикс ID | Ромб (правая панель) | Иконка (левая панель) | Вертикальный пунктир | Цвет |
|-----|-----------------|-----------|---------------------|----------------------|---------------------|------|
| **Regular** | Обычная веха | ▼В* | 14×14 px, фиолетовый ◆ | 14 px, фиолетовый | Нет | #9c27b0 |
| **PhaseGate** | Межэтапная веха | ▼ВР* | 14×14 px, фиолетовый ◆ | 14 px, фиолетовый | **Да** (серый, #616161) | #9c27b0 |
| **Legal** | Юридическая веха | ⚡ЮВ* | **20×20 px**, фиолетовый ◆ + красная тень | **18 px**, красный | **Да** (красный, #c62828) | #9c27b0 + #c62828 |
| **Control** | Контрольная веха | ⚡КВ* | 14×14 px, фиолетовый ◆ | 14 px, фиолетовый | **Да** (оранжевый, #e65100) | #9c27b0 |
| **Integration** | Интеграционная веха | ▼ИН* | 14×14 px, фиолетовый ◆ | 14 px, фиолетовый | Нет | #9c27b0 |

### 10.2. Вертикальный пунктир

Для вех типа **Legal** (ЮВ), **Control** (КВ) и **PhaseGate** (ВР) на диаграмме отображается **вертикальная пунктирная линия** на всю высоту диаграммы по позиции даты вехи.

- **Legal (⚡ЮВ):** красный пунктир (#c62828), `border-left: 2px dashed`
- **Control (⚡КВ):** оранжевый пунктир (#e65100), `border-left: 2px dashed`
- **PhaseGate (▼ВР):** серый пунктир (#616161), `border-left: 2px dashed`

Пунктир размещается на z-index: 3 (на уровне today-line), поверх зебры, но под барами задач. Линия проходит от верхнего края шкалы до низа всех строк — аналогично today-line.

### 10.3. Юридическая веха — увеличенный ромб

Вехи типа **Legal** (⚡ЮВ) отображаются **увеличенным ромбом** (20×20 px вместо стандартных 14×14 px) для визуального выделения юридически значимых дедлайнов. При наведении — красная тень (`drop-shadow`).

### 10.4. CSS-классы

| Класс | Описание |
|-------|----------|
| `.gantt-bar-milestone` | Базовый стиль ромба вехи (14×14 px) |
| `.milestone-legal` | Юридическая веха — увеличенный ромб + красная тень |
| `.gantt-milestone-icon` | Иконка вехи в левой панели (дерево) |
| `.gantt-milestone-legal` | Иконка юридической вехи — увеличена до 18 px, красный цвет |
