### BDR-030: Поисковое поле ДУЛ для дедупликации участников

Статус: Принято
Дата: 2026-09-10

Контекст:
При добавлении участника ООО оператор вводит данные документа, удостоверяющего личность (ДУЛ): тип, серию и номер. Дедупликация по отдельным полям (`dul_type_id + passport_series + passport_number`) ненадёжна — операторы могут перепутать порядок полей, ввести пробелы, заглавные/строчные буквы. Сравнение по трём полям одновременно повышает вероятность пропуска дубликата.

Решение:
Добавить в таблицу `board_participant` поисковое поле `dul_search_key` — нормализованная конкатенированная строка из типа ДУЛ, серии и номера. Дедупликация выполняется по одному полю.

**Формула вычисления:**
```
dul_search_key = normalize(dul_type_code) + "|" + normalize(passport_series) + "|" + normalize(passport_number)
```

**Нормализация:**
- Удалить все пробелы и дефисы
- Привести к верхнему регистру
- Тип ДУЛ — код из справочника (`ref_dul_type.code`), а не UUID

**Примеры:**

| Тип ДУЛ | Серия | Номер | dul_search_key |
|---------|-------|-------|----------------|
| 21 (Паспорт РФ) | 45 15 | 111222 | `21\|4515\|111222` |
| 21 (Паспорт РФ) | `4515` | `111 222` | `21\|4515\|111222` |
| 07 (Военный билет) | `АБ 123456` | — | `07\|АБ123456\|` |
| 12 (ВНЖ) | — | `A123456` | `12\|\|A123456` |

**Структура поля:**
```sql
ALTER TABLE board_participant ADD COLUMN dul_search_key varchar(200);
CREATE INDEX ix_board_participant_search_key ON board_participant(legal_entity_id, dul_search_key)
    WHERE dul_search_key IS NOT NULL;
```

**Дедупликация:**
```sql
-- Проверка дубликата
SELECT EXISTS(
    SELECT 1 FROM board_participant
    WHERE legal_entity_id = :leId
      AND is_active = TRUE
      AND dul_search_key = :searchKey
      AND id != :excludeId
);
```

Альтернативы:
1. **Сравнение по трём полям** — отклонено: ненадёжно при различиях в форматировании
2. **UNIQUE constraint на трёх полях** — отклонено: не учитывает нормализацию (пробелы, регистр)
3. **Только по INN** — отклонено: не все участники имеют ИНН (иностранцы, ФЛ без ИНН)

Последствия:
- Миграция БД: добавление колонки `dul_search_key` + индекса
- EF-маппинг: новое свойство в `BoardParticipant` + `BoardParticipantConfiguration`
- При сохранении участника: вычисление `dul_search_key` из `DulType.Code + PassportSeries + PassportNumber`
- Дедупликация: сравнение по одному полю вместо трёх
- Обратная совместимость: поле nullable, существующие записи обновляются при первом обращении
