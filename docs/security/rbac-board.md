# RBAC: Board Portal

> Связанные документы: [RBAC Admin Console](rbac-admin.md)

## Роли системы

| Код | Наименование | Назначаемая | Назначение |
|-----|-------------|-------------|------------|
| `SYS_ADMIN` | Системный администратор | Нет | Нет прямых прав в Board Portal. Назначает себе роль LE_ADMIN через Admin Console для доступа |
| `LE_ADMIN` | Администратор ЮЛ | Да | Управление конкретным ЮЛ |
| `SECRETARY` | Секретарь | Да | Организация заседаний, протоколы |
| `CEO` | Генеральный директор (ЕИО) | Да | Руководство юрлицом |
| `CHAIR_BOARD` | Председатель СД | Нет | Председательствование на заседаниях СД |
| `MEMBER_BOARD` | Член СД | Нет | Участие в заседаниях СД |
| `DEPUTY_CHAIR` | Зам. председателя СД | Нет | Замещение председателя |
| `EXTERNAL_DIRECTOR` | Внешний/Независимый директор | Нет | Независимый директор. Назначается через онбординг |
| `PARTICIPANT` | Участник ООО | Да | Участие в управлении ООО |
| `LAWYER` | Юрист | Да | Доступ к юридическим документам |
| `COMMITTEE_CHAIR` | Председатель комитета | Нет | Председатель комитета СД |
| `COMMITTEE_MEMBER` | Член комитета | Нет | Член комитета СД |
| `SHAREHOLDER` | Акционер | Нет | Участие в ОСА АО |

## Механизм определения доступа

Board Portal доступен **всем аутентифицированным** пользователям (`RequireAuthorization()` без RequireRole). Доступ к конкретным данным определяется **привязкой к ЮЛ** через `LegalEntityHelper`.

```
JWT-токен → userId
    ↓
User.Login → EcosystemParticipant.Login → LegalEntityId
    ↓
Данные фильтруются по LegalEntityId
```

### Исключения

- `PARTICIPANT` видит **только свои** запросы (`share_request WHERE user_id = currentUserId`)
- Публичные страницы (`/proposal`, `/onboarding`, `/login`, `/logout`) доступны без аутентификации

## Примечания

- **Информирование**: PARTICIPANT вызывает режим «Информирование» (как требование). У ГД — панель для просмотра.
- **Подача требований**: PARTICIPANT отправляет требования в общество.
- **Разбор требований**: MEMBER_BOARD или SECRETARY разбирают требования в рамках полномочий СД для формирования повестки заседания. У ГД — панель для просмотра.
- **Формирование документации**: CEO и LAWYER формируют документы для участников.
- **Просмотр документации**: PARTICIPANT просматривает предоставленную ему документацию.
- SECRETARY: подготовка СД, мероприятия по подписанию итогового протокола СД
- EXTERNAL_DIRECTOR: участие в СД и деятельности определённых комитетов (согласно законодательству)
