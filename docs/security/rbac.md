# Модель ролиевого доступа (RBAC)

## Обзор систем

| Система | URL | Назначение | Целевая аудитория |
|---------|-----|------------|-------------------|
| **Admin Console** | `:5001` | Администрирование: управление пользователями, ЮЛ, ролями, настройками | Системные администраторы |
| **Board Portal** | `:5002` | Рабочее пространство: участники, заседания, голосование, документы | Директора, Секретари, ГД, Участники |

## Роли системы

| Код | Наименование | Назначаемая | Назначение |
|-----|-------------|-------------|------------|
| `SYS_ADMIN` | Системный администратор | Нет | Полный доступ. Только через LDAP-группу `cn=SysAdmins` |
| `LE_ADMIN` | Администратор ЮЛ | Да | Управление конкретным ЮЛ |
| `SECRETARY` | Секретарь | Да | Организация заседаний, протоколы |
| `CEO` | Генеральный директор (ЕИО) | Да | Руководство юрлицом |
| `CHAIR_BOARD` | Председатель СД | Нет | Председательствование на заседаниях СД |
| `MEMBER_BOARD` | Член СД | Нет | Участие в заседаниях СД |
| `DEPUTY_CHAIR` | Зам. председателя СД | Нет | Замещение председателя |
| `EXTERNAL_DIRECTOR` | Внешний/Независимый директор | Нет | Независимый директор. Назначается через онбординг |
| `PARTICIPANT` | Участник ООО | Да | Участие в управлении ООО |
| `LAWYER` | Юрист | Да | Доступ к юридическим документам |
| `COMMITTEE_CHAIR` | Председатель комитета | Нет | Председатель комитета СД |
| `COMMITTEE_MEMBER` | Член комитета | Нет | Член комитета СД |
| `SHAREHOLDER` | Акционер | Нет | Участие в ОСА АО |

> **Назначаемая** — роль можно добавить/удалить через UI (вкладка «Роли» в карточке пользователя). Неназначаемые роли управляются только через LDAP или бизнес-процессы.

## Доступ к Admin Console

Admin Console доступен **только** для `SYS_ADMIN`. Все API-эндпоинты проверяют `RequireRole("SYS_ADMIN")`.

| Раздел | Путь | Доступ |
|--------|------|--------|
| Управление пользователями | `/users` | SYS_ADMIN |
| Управление сотрудниками/ЮЛ | `/access-management` | SYS_ADMIN |
| Справочник ролей | `/roles` | SYS_ADMIN |
| Советы директоров | `/boards` | SYS_ADMIN |
| Общие собрания (ОСА/ОСУ) | `/osa` | SYS_ADMIN |
| Шаблоны уведомлений | `/notification-templates` | SYS_ADMIN |

## Механизм определения доступа

Доступ определяется **не только ролью**, но и **привязкой к ЮЛ**:

```
JWT-токен → userId
    ↓
User.Login → EcosystemParticipant.Login → LegalEntityId
    ↓
Данные фильтруются по LegalEntityId
```

### Примеры

- **Участники**: `board_participant WHERE legal_entity_id = currentLeId`
- **Запросы участников**: `share_request WHERE legal_entity_id = currentLeId`
- **Настройки ЮЛ**: `legal_entity_board_settings WHERE legal_entity_id = currentLeId`

### Исключения

- `SYS_ADMIN` видит **все** ЮЛ и **все** данные
- `PARTICIPANT` видит **только свои** запросы (`share_request WHERE user_id = currentUserId`)
- Публичные страницы (`/proposal`, `/onboarding`, `/login`, `/logout`) доступны без аутентификации

## ЕДИН-режимы

| Режим | `Edin:Enabled` | Поведение |
|-------|---------------|-----------|
| **Выключен** | `false` | `mpi_master_id` не заполняется автоматически |
| **Включён** | `true` | После сохранения участника с ПДн → ЕДИН resolve → `ecosystem_participants.mpi_master_id` → поиск УЗ в `users` → `user_id` |

### Источники MPI MasterId

| Таблица | Источник | Когда заполняется |
|---------|----------|-------------------|
| `users.mpi_master_id` | LDAP/AD (синхронизация) | При синхронизации из каталога |
| `ecosystem_participants.mpi_master_id` | ЕДИН API (resolve по ДУЛ/ИНН/СНИЛС) | После сохранения участника с ПДн |

### Поиск УЗ по MasterId

1. Поиск в `users` по `mpi_master_id`
2. Если не найдена → `user_id` участника остаётся NULL
3. Если найдена → автоматическая привязка `ecosystem_participants.user_id = users.id`
