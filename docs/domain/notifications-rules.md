# Правила уведомлений

## Обзор системы

Система уведомлений фиксирует факт формирования уведомления в таблице `notifications` и в логе приложения. Реальная отправка по внешним каналам (Email/SMS/Push) не выполняется — заголовок каждого уведомления содержит префикс «ИМИТАЦИЯ ОТПРАВКА ПО email».

Каждое уведомление содержит:
- **Тип** — код из справочника `ref_notification_type`
- **Заголовок** — начинается с «ИМИТАЦИЯ ОТПРАВКА ПО email — »
- **Тело** — шаблон письма, сформированный `NotificationTextBuilder`
- **Ссылка (URL)** — путь в Board Portal для просмотра связанной сущности
- **Получатель** — `user_id` в таблице `notifications`

## Справочник типов (`ref_notification_type`)

| Код | Наименование | Получатель | Описание |
|-----|-------------|------------|----------|
| `MEETING_SUMMONS` | Созыв заседания СД | Члены СД | Созыв очного/заочного/смешанного заседания |
| `VOTE_REMINDER` | Напоминание о голосовании | Члены СД | Напоминание о необходимости проголосовать |
| `PROTOCOL_SIGNED` | Протокол подписан | Члены СД | Протокол заседания подписан и доступен |
| `COMMITTEE_PROTOCOL_SIGNED` | Протокол комитета подписан | Члены комитета | Протокол заседания комитета подписан |
| `VOTE_DEADLINE` | Завершение голосования | Члены СД | Голосование завершено, результаты в протоколе |
| `CHAIRMAN_NOMINATION` | Сбор кандидатур — Председатель СД | Члены СД | Сбор предложений кандидатур на должность |
| `DEPUTY_CHAIRMAN_NOMINATION` | Сбор кандидатур — Зам. председателя СД | Члены СД | Сбор предложений кандидатур на должность |
| `CHAIRMAN_CONSENT` | Согласие на должность Председателя СД | Кандидат | Запрос согласия на выдвижение |
| `DEPUTY_CHAIRMAN_CONSENT` | Согласие на должность Зам. председателя СД | Кандидат | Запрос согласия на выдвижение |
| `GENERAL` | Общее уведомление | Задаётся вызывающим кодом | Произвольное уведомление |
| `COLLECTIVE_DEMAND_THRESHOLD` | Коллективное требование — порог достигнут | Участники | Порог коллективного требования достигнут |
| `COLLECTIVE_DEMAND_DECISION` | Коллективное требование — решение ГД | Участники | ГД принял решение по коллективному требованию |
| `SHARE_REQUEST_ACCEPTED` | Требование принято ГД | Автор запроса / участники коллективного | ГД принял требование участника |
| `SHARE_REQUEST_VISIBLE_TO_ALL` | Новое требование — видно всем ГД | Ген. директора (CEO) | Поступило требование с `visible_to_all = true` |

## Шаблоны тел писем

### MEETING_SUMMONS (первое заседание)

**Заголовок:** `ИМИТАЦИЯ ОТПРАВКА ПО email — Созыв первого заседания совета директоров {legalEntityName}`

**Тело:**
> Уважаемый член совета директоров!
>
> Уведомляем вас о созыве первого (организационного) заседания совета директоров {legalEntityName}.
>
> Дата и время: {date} в {time}
> Форма проведения: очная (совместное присутствие)
>
> Повестка дня:
> 1. Избрание Председателя совета директоров.
> 2. Избрание заместителя Председателя совета директоров.
> 3. Избрание секретаря совета директоров.
> 4. Формирование комитетов совета директоров.
>
> В соответствии с п. 1 ст. 68 Федерального закона № 208-ФЗ первое заседание совета директоров проводится только в очной форме.

### SHARE_REQUEST_ACCEPTED

**Заголовок:** `ИМИТАЦИЯ ОТПРАВКА ПО email — Требование принято`

**Тело:**
> Уважаемый(-ая) {creatorName}!
>
> Ваше требование (тип: {requestType}) по обществу «{legalEntityName}» принято Генеральным директором.
>
> Комментарий ГД: {ceoComment}
>
> Подробности: {url}

### SHARE_REQUEST_VISIBLE_TO_ALL

**Заголовок:** `ИМИТАЦИЯ ОТПРАВКА ПО email — Новое требование участника`

**Тело:**
> Уважаемый Генеральный директор!
>
> Поступило требование участника {participantName} (доля {sharePercent}%) по обществу «{legalEntityName}».
>
> Тип требования: {requestType}
>
> Ознакомьтесь с требованием: {url}

## Правила определения получателей

| Сценарий | Получатель | Как определить |
|----------|-----------|----------------|
| Заседание СД | Члены СД | `User` → `UserRole` (role = `MEMBER_BOARD`) + `BoardMember.UserId` |
| Запрос принят ГД | Автор запроса | `ShareRequest.CreatedBy` → `User` |
| Коллективный запрос принят | Участники запроса | `ShareRequestSupport` → `BoardParticipant` → `Person` → `User` |
| Запрос виден всем ГД | Ген. директора | `UserRole` (role = `CEO`) → `User` |
| Номинация председателя | Члены СД | `BoardMembers` с `UserId` |
| Согласие на должность | Кандидат | `BoardMember.UserId` |

---

## Технический долг

- **Отсутствие привязки CEO к ЮЛ.** `UserRole` хранит только связь User↔Role без контекста ЮЛ. Уведомления `SHARE_REQUEST_VISIBLE_TO_ALL` отправляются всем CEO без фильтрации по ЮЛ.
