# Модель данных диаграммы Ганта

Диаграммы Ганта в проекте описывают подготовку к общим собраниям — [ООСУ](oosu-gantt.md) (для ООО) и [ГОСА](gosa-gantt.md) (для АО). В этой статье — устройство модели, условные обозначения и соглашения, общие для обеих диаграмм.

---

## 1. Столбцы таблицы

Каждая задача описывается строкой со следующими полями:

| Столбец | Тип | Описание |
|---------|-----|----------|
| **ID** | `строка` | Уникальный код задачи. Префикс обозначает категорию (см. раздел 2), номер — порядок в категории. Пример: `Б1`, `А2`, `П3` |
| **Задача** | `строка` | Название задачи — что именно делается |
| **Исполнитель** | `строка` | Роль, выполняющая задачу. Может указывать делегирование: `Гендиректор → бухгалтерия`. Если роль отсутствует в компании — выполняет гендиректор или его заместитель |
| **Длительность** | `целое` | Рабочих дней (р.д.). Для вех — `0` |
| **Начало** | `дата` | Дата старта задачи. Для вех — дата наступления |
| **Конец** | `дата` | Дата завершения. Для вех — равна дате начала |
| **Предшественники** | `строка` | ID задач, которые должны быть завершены до старта данной. `—` означает отсутствие зависимости. Несколько предшественников разделяются запятыми |
| **Примечание** | `строка` | Детали выполнения, ссылки на таблицы СЭД/рассылок, особые условия |

## 2. Категории задач (префиксы ID)

### 2.1. Общие для ООСУ и ГОСА

| Префикс | Категория | Примеры |
|---------|-----------|---------|
| **Б\*** | Бухгалтерия | `Б1` — постановка задачи, `Б2` — подготовка отчётности |
| **Р\*** | Ревизионная комиссия (ревизор) | `Р1` — передача документов, `Р2` — проверка, `Р3` — приём заключения |
| **А\*** | Аудитор | `А1` — договор, `А2` — передача документов, `А3` — аудит, `А4` — приём заключения |
| **П\*** | Подготовка к собранию | `П1` — повестка, `П2` — сборка материалов, `П3` — рассылка |
| **Д\*** | Доп. вопросы участников/акционеров | `Д1` — приём, `Д2` — рассмотрение, `Д3` — уведомление |
| **ОС\*** | Проведение собрания и завершение | `ОС1` — собрание, `ОС2` — протокол, `ОС3` — ФНС, `ОС4` — банк |
| **Н\*** | Нотариус | `Н1` — запрос выписки из ЕИС |
| **▼В\*** | Вехи (нулевая длительность) | `▼В1` — отчётность готова, `▼В2` — заключения получены |

### 2.2. Специфичные для ГОСА

| Префикс | Категория | Примеры |
|---------|-----------|---------|
| **СД\*** | Совет директоров | `СД1` — рассмотрение предложений, `СД2` — утверждение отчёта, `СД3` — решение о созыве |
| **АК\*** | Акционеры | `АК1` — приём предложений в повестку |
| **РГ\*** | Регистратор | `РГ1` — запрос списка, `РГ2` — быстрый список, `РГ3` — полный список, `РГ4` — проверка |

---

## 3. Вехи

**Веха** (▼В\*) — контрольная точка с нулевой длительностью. Наступает, когда все её предшественники завершены. Используется для отметки ключевых событий:

- готовность отчётности
- получение заключений
- рассылка уведомлений
- проведение собрания

Вехи не имеют исполнителя — они являются следствием завершения предшествующих задач.

---

## 4. Фазы

Задачи группируются в **фазы** — хронологические блоки, разделённые строками-заголовками в таблице. Фаза не является строкой с ID — это визуальный разделитель:

```
| **→ Фаза 1: Запуск (январь)** |
| Б1 | Постановка задачи бухгалтерии | ... |
| **→ Фаза 2: Подготовка отчётности (январь – февраль)** |
| Б2 | Подготовка годового отчёта | ... |
```

Фазы едины для всех сценариев внутри одной диаграммы, но длительность фазы зависит от сценария (например, с аудитором фаза проверки длиннее).

---

## 5. Критический путь

В начале каждого сценария указана цепочка задач, образующих критический путь:

```
Критический путь: Б2 → А3 → А4 → П2 → П3 → ОС1 (≈53 р.д.)
```

**Критический путь** — самая длинная нерастяжимая последовательность зависимых задач. Задержка любой задачи на этом пути сдвигает дату собрания. Задачи на критическом пути помечены ⚠️ в столбце «Примечание».

---

## 6. Сценарии

Одна диаграмма может содержать несколько сценариев — вариантов расчёта для разных условий:

- **ООСУ:** сценарий А (с аудитом) и сценарий Б (без аудита)
- **ГОСА:** один сценарий (с аудитом, т.к. для ПАО обязателен)

Сценарии различаются:
- набором задач (в сценарии Б исключаются задачи аудитора)
- критическим путём
- датами начала/конца задач

Остальные параметры (фазы, вехи, исполнители) — общие.

## 7. Документооборот (СЭД, заказные, рассылки)

Каждая диаграмма дополнена тремя справочными таблицами, описывающими артефакты, которые создаются и перемещаются в процессе:

| Таблица | Содержит | Тип артефактов |
|---------|----------|----------------|
| **СЭД** (индексы `С*`) | Внутренние документы, проходящие через систему электронного документооборота | Приказы, поручения, проекты, служебные записки. Получатель — внутри компании |
| **Заказные / email** (индексы `З*`) | Отправления, для которых важен факт и дата отправки | Уведомления, заявления. «Заказное письмо» — только через Почту России (квитанция с трек-номером). Электронная подача в ФНС — с УКЭП |
| **Рассылки** (индексы `Р*`) | Что, кому и в какой срок направляется | Уведомления участникам/акционерам, копии протоколов. **Не включает** передачу рабочих материалов (ревизору, аудитору, регистратору) — это задачи, а не рассылки |

Связь между Гантом и таблицами документооборота — через индексы в столбце «Примечание»:

```
| П3 | Рассылка уведомлений | ... | [З1](#z1), [Р1](#r1) |
```

Это означает: задача `П3` создаёт заказное отправление `З1` и соответствует строке `Р1` в таблице рассылок.
