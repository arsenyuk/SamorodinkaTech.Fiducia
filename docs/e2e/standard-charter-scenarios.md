# Сквозные E2E-сценарии для 36 типовых уставов ООО

## Назначение

Документ описывает 36 сквозных (end-to-end) сценариев тестирования, покрывающих все типовые уставы ООО, утверждённые Приказом Минэкономразвития России от 01.08.2018 № 411.

Каждый сценарий проверяет полный жизненный цикл настройки юридического лица: от сброса базы данных до сохранения ЮЛ с выбранным типовым уставом.

---

## Предусловия

- Запущена инфраструктура: PostgreSQL, OpenLDAP, phpLDAPadmin, MinIO
- Запущены приложения: Admin Console (порт 5001), Board Portal (порт 5002)
- Auth:Method = "Basic" (для тестов)
- Playwright браузер установлен (`dotnet tool install Microsoft.Playwright` + `pwsh bin/Debug/net9.0/playwright.ps1 install`)

---

## Общая структура сценария

Каждый из 36 сценариев (устав №01 — №36) выполняет следующие шаги:

### Шаг 0: Удаление тестовых пользователей из LDAP

**Действие:** Выполнить `ldapdelete` для удаления всех записей `inetOrgPerson` из `ou=users` и очистить ссылки на них в группах.

**Цель:** Обеспечить чистоту теста — отсутствие остаточных учётных записей от предыдущих запусков. Это критически важный шаг для воспроизводимости, так как:
- Повторное создание пользователя с тем же `uid` приведёт к ошибке LDAP (Duplicate entry)
- Остаточные членства в группах могут повлиять на разрешения

**Реализация:** `LdapHelper.DeleteAllTestUsersAsync()` — использует CLI-утилиты `ldapsearch`, `ldapmodify`, `ldapdelete` для:
1. Поиска всех `inetOrgPerson` в `ou=users,dc=bryansk-arsenal,dc=local`
2. Удаления пользователя из всех групп (`member` attribute в `groupOfNames`)
3. Удаления самой записи пользователя

### Шаг 1: Сброс базы данных

**Действие:** Выполнить DbReset с флагом `--no-demo`.

```bash
dotnet run --project src/Tools/DbReset -- --no-demo
```

**Ожидаемый результат:** БД содержит только справочные данные (02_seed.sql):
- Системный пользователь
- 13 ролей (SYS_ADMIN, SECRETARY, CHAIR_BOARD, MEMBER_BOARD, CEO, LE_ADMIN и др.)
- 7 типов ОКОПФ (ПАО, НАО, АО, ООО, ГУП, ФГУП, МУП)
- 36 типовых уставов ООО
- Шаблоны организационных мероприятий
- Справочники (типы документов, статусы и т.д.)

Демо-данные (03_demo.sql) НЕ применяются: нет компаний из SPARK, нет demo-пользователей.

### Шаг 2: Создание пользователя в OpenLDAP

**Действие:** Через phpLDAPadmin (http://localhost:8082) создать нового пользователя.

Данные пользователя:

| Поле | Значение |
|------|----------|
| objectClass | inetOrgPerson |
| uid | `test.gd` |
| cn | Тестов Тест Тестович |
| sn | Тестов |
| givenName | Тест |
| mail | test.gd@test.local |
| userPassword | test1234 |
| DN | cn=Тестов Тест Тестович,ou=users,dc=bryansk-arsenal,dc=local |

**Дополнительно:** Добавить пользователя в группу `cn=BoardOfDirectors,ou=groups,dc=bryansk-arsenal,dc=local`.

### Шаг 3: Авторизация системного администратора

**Действие:** Открыть Admin Console (http://localhost:5001/login), войти как SYS_ADMIN.

| Параметр | Значение |
|----------|----------|
| URL | `http://localhost:5001/login` |
| Режим авторизации | Basic (выбор из списка) |
| Пользователь | Васильева Вера Васильевна (Корпоративный секретарь) |
| Пароль | 1 |

**Ожидаемый результат:** Редирект на `/main`. В localStorage сохранены: currentUserId, currentUserName, currentUserRole = "SYS_ADMIN".

### Шаг 4: Переход в режим Пользователи

**Действие:** Перейти на страницу `/access-management`.

**Ожидаемый результат:** Отображается форма "Сотрудники и доступ" с:
- Выпадающий список ЮЛ
- Кнопка "+ Создать ЮЛ"
- Вкладки "Сотрудники" и "Внешние лица"
- Форма добавления сотрудника

### Шаг 5: Создание юридического лица (ООО)

**Действие:** Кликнуть "+ Создать ЮЛ", заполнить форму.

| Поле | Значение (пример для устава №01) |
|------|----------------------------------|
| Наименование | Общество с ограниченной ответственностью «Тестовый Устав 01» |
| ИНН | 7701345678 |

**Ожидаемый результат:** Модальное окно закрывается. ЮЛ появляется в выпадающем списке.

**Формирование ИНН:** Для каждого устава генерируется уникальный ИНН по формуле `77{NN}345678`, где `NN` — номер устава (01-36).

### Шаг 6-7: Добавление сотрудника и назначение ролей

**Действие:** Заполнить форму "Добавить сотрудника" и добавить пользователя дважды (с разными ролями).

#### Первая запись — Администратор ЮЛ:

| Поле | Значение |
|------|----------|
| Фамилия | Тестов |
| Имя | Тест |
| Отчество | Тестович |
| Должность | Генеральный директор |
| Логин | test.gd |
| Роль | LE_ADMIN (Администратор ЮЛ) |

#### Вторая запись — Генеральный директор:

| Поле | Значение |
|------|----------|
| Фамилия | Тестов |
| Имя | Тест |
| Отчество | Тестович |
| Должность | Генеральный директор |
| Логин | test.gd |
| Роль | CEO (Генеральный директор) |

**Ожидаемый результат:** В таблице сотрудников отображается "Тестов Тест Тестович" с ролями "Администратор ЮЛ" и "Генеральный директор".

### Шаг 8: Выход из Admin Console

**Действие:** Выполнить POST-запрос на `/api/session/logout` и очистить localStorage.

**Ожидаемый результат:** HttpOnly cookie с JWT удаляется. Пользователь не авторизован.

### Шаг 9: Авторизация Генерального директора в Board Portal

**Действие:** Открыть Board Portal (http://localhost:5002/login), войти как GD.

| Параметр | Значение |
|----------|----------|
| URL | `http://localhost:5002/login` |
| Режим авторизации | Basic (выбор из списка) |
| Пользователь | Тестов Тест Тестович (Генеральный директор) |
| Пароль | 1 |

**Ожидаемый результат:** Редирект на `/main`.

### Шаг 10: Заполнение полей ЮЛ и выбор типового устава

**Действие:** Перейти на `/legal-entities`, заполнить недостающие поля и выбрать устав.

#### Вкладка "Карточка ЮЛ" (таб 0):

| Поле | Значение (пример для устава №01) |
|------|----------------------------------|
| Краткое наименование | ООО «Тест 01» |
| ОГРН | 1013456789012 |
| ОКОПФ | ООО (12300) |

#### Вкладка "Устав" (таб 3):

| Поле | Значение |
|------|----------|
| Номер типового устава | 01 (или 02-36 в зависимости от сценария) |

**Ожидаемый результат:** Устав успешно выбран. Параметры устава отображаются на странице.

### Шаг 11: Сохранение и проверка отсутствия ошибок

**Действие:** Нажать кнопку "Сохранить".

**Ожидаемый результат:**
- Спиннер загрузки появляется и исчезает
- Отображается сообщение об успехе: "Настройки сохранены"
- **Отсутствуют** alert-danger (красные сообщения об ошибках)

  --filter "E2E_StandardCharterTests" \

## Требования к среде

| Компонент | Минимальная версия | Порт |
|-----------|-------------------|------|
| .NET SDK | 9.0 | — |
| PostgreSQL | 16 | 5434 |
| OpenLDAP (bitnami) | 2.6 | 389 |
| phpLDAPadmin | latest | 8082 |
| Admin Console | net9.0 | 5001 |
| Board Portal | net9.0 | 5002 |
| Playwright | 1.52.0 | — |

### Быстрый старт инфраструктуры:

```bash
# Запустить PostgreSQL
docker-compose up -d postgres

# Запустить OpenLDAP + phpLDAPadmin
docker-compose -f docker-compose.ldap.yml up -d

# Загрузить seed-данные в LDAP
docker exec -i openldap ldapadd -x -D "cn=admin,dc=bryansk-arsenal,dc=local" -w ldappassword < tools/ldap/seed-bitnami.ldif

# Запустить приложения
dotnet run --project SamorodinkaTech.Fiducia.AdminConsole &
dotnet run --project SamorodinkaTech.Fiducia.BoardPortal &

# Установить Playwright браузер
pwsh tests/SamorodinkaTech.Fiducia.Tests.Functional/bin/Debug/net9.0/playwright.ps1 install
```

## Возможные проблемы и решения

| Проблема | Решение |
|----------|---------|
| phpLDAPadmin недоступен | Убедиться, что `docker-compose -f docker-compose.ldap.yml up -d` выполнен |
| DbReset не находит `tools/db` | Установить переменную `FIDUCIA_REPO` или запускать из корня репозитория |
| Браузер Playwright не установлен | `pwsh playwright.ps1 install` в директории с тестами |
| Тест завис на登录 | Проверить, что Auth:Method = "Basic" в `appsettings.json` обоих порталов |
| Нет опции "Васильева" в dropdown | Выполнить шаг 1 (сброс БД) — она создаётся в seed-данных |
| Нет опции "Тестов" в Board Portal dropdown | Пользователь должен быть создан в шаге 2 и добавлен в шаге 6-7 |
