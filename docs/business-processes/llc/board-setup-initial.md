# Первичный ввод состава Совета директоров ООО

> **Связанные документы:**
> - [Нетиповой устав ООО](non-standard-charter.md)
> - [Назначение руководства ООО](llc-management-appointment.md)

## Обзор

Для ООО с нетиповым (индивидуальным) уставом Совет директоров является **правом**, а не обязанностью. Если устав предусматривает создание СД, администратор (ГД) должен ввести его состав при первичной настройке.

## Когда используется

- ООО с **нетиповым уставом** (`StandardCharterId == null`)
- В уставе установлен флаг `HasBoardOfDirectors = true`
- Это **первичный ввод** — состав СД ещё не определён

## Три варианта структуры СД

Структура СД зависит от положений устава ООО:

| Вариант | Председатель СД | Зам. председателя | Секретарь СД |
|---------|----------------|-------------------|--------------|
| **1** | ✓ (обязательно) | ✗ | ✗ |
| **2** | ✓ (обязательно) | ✓ | ✗ |
| **3** | ✓ (обязательно) | ✗ | ✓ |

Настройка варианта выполняется на странице ЮЛ, вкладка «Совет директоров» (флаги `DeputyChairProvided`, `SecretaryProvided`).

## Порядок действий

### 1. Настройка ЮЛ (вкладка «Устав»)
1. Выбрать нетиповый устав (не номер 01–36)
2. Установить «Совет директоров: Да»
3. Настроить структуру СД на вкладке «Совет директоров» (флаги зам. председателя и секретаря)

### 2. Добавление участников общества
Перейти на страницу `/participants` и добавить участников ООО (ФИО, ДУЛ, доли).

### 3. Первичный ввод состава СД
1. На вкладке «Совет директоров» нажать «Первичный ввод состава СД →»
2. Откроется страница `/board-setup`
3. Нажать **«Добавить участника СД»** — откроется модальная форма:
   - Выбрать роль (Председатель СД / Зам. председателя / Секретарь СД / Член СД)
   - Ввести ФИО, ДУЛ, ИНН, СНИЛС
   - Сохранить
4. Или нажать **«Найти среди участников/сотрудников»** — поиск по существующим участникам ЮЛ:
   - Ввести запрос (ФИО, ИНН, паспорт)
   - Выбрать участника из результатов
   - Назначить роль
5. Повторять пока все роли не назначены
6. Нажать **«Сохранить состав СД»**

### 4. ЕДИН-матчинг
При добавлении/выборе участника автоматически запускается попытка привязки к экосистеме через ЕДИН API:
- Если учётка найдена → статус «✓ Привязан»
- Если не найдена → статус «✗ Не привязан» (процесс продолжается)

## Валидация (серверная)

| Правило | Описание |
|---------|----------|
| Ровно 1 Председатель | Обязательно один участник с ролью CHAIR |
| Не более 1 Зам. председателя | Максимум один участник с ролью DEPUTY_CHAIR |
| Не более 1 Секретаря | Максимум один участник с ролью SECRETARY |
| Нет дублей | Один участник не может иметь одну роль дважды |
| Участники активны | Все назначенные участники должны быть активны (`is_active = true`) |

## Хранение данных

| Таблица | Назначение |
|---------|-----------|
| `board_participant` | Участники общества (ФИО, ДУЛ, ИНН) |
| `board_participant_role` | Роли участников в СД (junction: участник ↔ роль) |
| `ref_board_roles` | Справочник ролей: CHAIR, DEPUTY_CHAIR, SECRETARY, MEMBER и др. |

## Интеграция с wizard'ом встречи ОСУ

При создании встречи ОСУ (шаг «Совет директоров») состав СД предзаполняется из `board_participant_role`:
- Если есть записи в `board_participant_role` → строки заполняются автоматически
- Если нет → создаются пустые строки (текущее поведение)

## API

| Метод | URL | Назначение |
|-------|-----|-----------|
| GET | `/api/v1/board-setup` | Загрузка состава СД + настроек |
| GET | `/api/v1/board-setup/search-participants` | Поиск участников ЮЛ |
| POST | `/api/v1/board-setup/validate` | Валидация назначений |
| POST | `/api/v1/board-setup/save` | Сохранение состава СД |
| POST | `/api/v1/board-setup/remove-role` | Удаление роли участника |
