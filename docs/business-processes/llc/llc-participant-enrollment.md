# Заведение участников ООО в систему

## Обзор

Участники ООО — физические или юридические лица, владеющие долями в уставном капитале. В системе участники представляются двумя сущностями:

| Сущность | Таблица БД | Создаётся | Содержит |
|----------|-----------|-----------|----------|
| **EcosystemParticipant** | `ecosystem_participant` | Admin Console | Login, привязка к User, МasterId |
| **BoardParticipant** | `board_participant` | Board Portal | ФИО, ДУЛ, ИНН, доля, статус |

> **Правило:** Admin Console создаёт **только** User + EcosystemParticipant + Employee + Role. BoardParticipant (с ДУЛ и долей) создаётся **только** через Board Portal.

---

## Процесс добавления участника

### Этап 1: Подготовка (Admin Console)

1. SYS_ADMIN или LE_ADMIN создаёт ЮЛ (ООО, ОКОПФ 12300) через Admin Console → `/access-management`
2. Назначает сотрудников (LE_ADMIN, CEO, PARTICIPANT) через «Добавить сотрудника»
3. Для каждого сотрудника создаётся: `User` (LDAP login) + `EcosystemParticipant` (login + LegalEntityId) + `Employee` + `UserRole`

> **Роль PARTICIPANT** — обязательна для доступа к подаче требований, просмотру документов, информированию.

### Этап 2: Добавление участника (Board Portal)

1. LE_ADMIN или CEO входит в Board Portal
2. Переходит на страницу «Участники» → `/participants`
3. Кликает «Добавить участника»
4. Заполняет форму:
   - **Тип участника**: ФЛ / ЮЛ / ИП
   - **ФИО** (для ФЛ) или **Наименование** (для ЮЛ)
   - **Тип ДУЛ** (справочник `ref_dul_type`): паспорт РФ (21), военный билет (07), ВНЖ (12), иные (91)
   - **Серия и номер** ДУЛ (для типов с `has_series=true`)
   - **ИНН** (для ФЛ или ЮЛ)
   - **Доля** (процент и номинальная стоимость)
5. Сохраняет → `POST /api/participants`

### Этап 3: ЕДИН binding (автоматически)

После сохранения BoardParticipant система автоматически запускает `TriggerEdinBindingAsync`:

1. Вызывает ЕДИН API (`POST /persons/resolve`) с ПДН + ДУЛ
2. Получает `MasterId` — уникальный идентификатор человека в ЕДИН
3. Привязывает `MasterId` к `EcosystemParticipant`
4. Ищет существующий `User` по `MpiMasterId` в БД
5. Если найден → связывает `BoardParticipant` с `EcosystemParticipant`

> **Роль PARTICIPANT** назначается **автоматически** при привязке BoardParticipant к EcosystemParticipant.

### Этап 4: Настройка ГД (опционально)

Если участник — Генеральный директор:
1. На странице ЮЛ (вкладка «ГД») выбирается участник из реестра
2. При сохранении запускается отдельный ЕДИН resolve для ГД
3. Система ищет `EcosystemParticipant` по `MasterId + LegalEntityId`
4. Привязывает `BoardParticipant` к найденному `EcosystemParticipant`
5. Назначает роль **CEO** если есть связанная `User`-запись

## Дедупликация

### Ключи дедупликации

| Тип участника | Ключ | Пример |
|---------------|------|--------|
| ФЛ (ДУЛ) | `dul_search_key` (нормализованная строка) | `ffffffff-ffff-ffff-ffff-ffffffffff10\|4515\|111222` |
| ФЛ (ИНН) | `person_inn` | 7708889990 |
| ЮЛ (ИНН) | `company_inn` | 7701234567 |
| ЕДИН (MasterId) | `mpi_master_id` | GUID из ЕДИН API |

**Нормализация `dul_search_key`:** `DulTypeId | normalized_series | normalized_number`
- Удаление пробелов и дефисов
- Верхний регистр
- Сравнение по одному полю вместо трёх

### Правила дедупликации

**При добавлении участника (POST /api/participants):**

1. **Проверка по ДУЛ**: вычисляется `dul_search_key` (нормализованная строка `DulType|Series|Number`). Если совпадает с **активным** участником в этом же ЮЛ → **ошибка**
2. **Проверка по INN**: если `person_inn` / `company_inn` совпадает с **активным** участником в этом же ЮЛ → **ошибка**
3. **Неактивные участники**: совпадение с **удалённым** (неактивным) участником → **допустимо** (повторное добавление)
4. **Разные ЮЛ**: совпадение с участником **другого** ЮЛ → **допустимо** (один человек может быть участником нескольких ООО)

**При ЕДИН binding (TriggerEdinBindingAsync):**

1. Если `MasterId` уже привязан к **текущему** `EcosystemParticipant` → пропуск
2. Если `MasterId` привязан к **другому** `EcosystemParticipant` в этом ЮЛ → привязать BoardParticipant к **существующему** EcosystemParticipant
3. Если `MasterId` не найден → привязать к текущему EcosystemParticipant

### Сообщения об ошибках

| Ситуация | Сообщение |
|----------|-----------|
| Дубликат ДУЛ | «Участник с таким документом (Паспорт гражданина РФ) уже добавлен» |
| Дубликат ИНН | «Участник с таким ИНН уже добавлен» |
| Дубликат ЮЛ ИНН | «Юридическое лицо с таким ИНН уже добавлено» |

## Источники данных

| Источник | Что даёт | Когда |
|----------|----------|-------|
| LDAP | Login, ФИО, email | При входе пользователя |
| Admin Console | User + EcosystemParticipant + Employee + Role | Назначение сотрудников |
| Board Portal API | BoardParticipant (ДУЛ + доля) | Добавление участника |
| ЕДИН API | MasterId (уникальный идентификатор ФЛ) | Fire-and-forget после сохранения |
| СПАРК API | Данные о ЮЛ-участниках | Импорт из СПАРК (опционально) |

### Требования к тестовым данным

Для теста ВОСУ (entity 67) требуются **два уникальных логина**:

| Роль | Логин | Данные |
|------|-------|--------|
| ГД (CEO) | `ivanov.tr` | Назначается через Admin Console |
| Участник (PARTICIPANT) | `petrova.ms67` | Добавляется через Board Portal с ДУЛ |

> GD и участник — **разные** пользователи. Один логин не может быть и ГД, и участником одновременно (конфликт при добавлении через `AddEmployeeAsync`).
